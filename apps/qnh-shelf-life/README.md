# 鲜期 · 扫 SKU 管理保质期

扫描牵牛花 SKU，实时查回商品名称、规格和图片；拍摄生产日期与保质期，由员工清点填写件数，自动计算到期日期并保存批次。

正式手机入口：https://qnh-shelf-life-api.w792294944.workers.dev/ 。苹果使用 Safari 分享菜单添加到主屏幕，安卓从浏览器安装或添加到桌面。GitHub Pages 入口 https://wzz79229.github.io/qnh/shelf-life/ 也保留；苹果等限制第三方 Cookie 的浏览器请使用前面的同域入口。

## 先接入牵牛花

现可单独运行 [local-query/连接牵牛花.cmd](local-query/连接牵牛花.cmd)，在独立 Edge 窗口亲自登录牵牛花、进入商品主档，然后按提示输入 SKU，核对查回的名称、规格和主图。此入口无需 GitHub 令牌或 Cloudflare 连接密钥，不保存商品查询结果。详细步骤见 [本机连接说明](local-query/README.md#先连接牵牛花)。

历史本机工具曾完成真实 SKU 查询验证；该结果不能代表手机内置登录、SKU 查询或批次保存已经完成实机验收。

当前主流程为鲜期内置牵牛花登录：员工在鲜期窗口内完成官方登录，服务端确认已进入官方牵牛花登录后的界面、识别并绑定实际租户后，自动进入保质期管理。登录阶段没有员工审批、手动确认或商品查询步骤。不同租户的数据分别保存到私有 bzq 的 data/tenants/<可信租户编号>/shelf-life.json，不能互相读取；不再固定某个租户或共用旧批次文件。管理员 GitHub App 已授权，员工无需配置 GitHub。此版本是免费额度限时试用，真实登录、查询与保存仍须现场验收。详见 [手机登录说明](backend/PHONE_LOGIN.md)。

## 使用流程

1. 在鲜期内完成牵牛花登录后，点“扫描 SKU 建档”。可实时相机扫码，也可拍 SKU 码；支持扫描枪输入或粘贴 SKU。身份未确认时保持登录页，不能用团队口令或旧 Cookie 代替牵牛花登录。
2. 点“查询牵牛花”，由当前手机对应的独立会话查回精确 SKU 的商品名称、规格和页面实际提供的商品图片。普通商品条码不会当成 SKU。编号始终作为字符串，保留前导零和长编号。
3. 核对商品后，拍清包装上的生产日期和保质期；可分开补拍，最多 3 张。照片仅在手机本页内存里用于 OCR，不上传，不进入备份或新批次，不保存到 GitHub；确认或关闭后释放临时照片。
4. 员工清点后填写这一生产日期的件数。必填 1 至 1000000 的整数，不从包装净含量推算，也不默认 1 件。
5. 核对生产日期、保质期和计算出的到期日期后保存。同 SKU 的不同生产日期分别建批次；重复 SKU 和生产日期会要求核对，不自动合并数量。

到期日期按生产日期加保质期计算。天按日历天计算，月/年超出目标月天数时取月末。生产日期在未来、日期或单位缺失、多个识别值冲突，以及包装明确到期日与计算值冲突时不能保存，须补拍。到期当天单独提醒；默认紧急临期 7 天、即将临期 30 天。

## 实时查询与历史本机工具

不再加载、搜索或同步整份商品库。每次扫码都在当前手机对应的独立牵牛花会话中查询指定 SKU，只读取该商品字段，并检查新的商品响应与页面结果一致。登录阶段不自动选择或查询商品。未找到、多个匹配、登录失效、缺图、页面变更和超时会明确失败，不从旧快照回退。

`local-query/` 仅保留为独立电脑查询和历史桥接工具，不能授权手机登录；当前手机主流程不依赖电脑程序，也不使用 GitHub 商品查询队列。

安装、密钥配置与启动见 [local-query/README.md](local-query/README.md)。源码和模拟测试完成不代表手机内置登录、查询与保存已经验收，仍需真实账号和商品核验。

## 管理员配置

管理员采用 GitHub App 一次安装授权，仅选私有 `Wzz79229/bzq`。设置步骤见 [GitHub App 配置](backend/GITHUB_APP_SETUP.md)。Cloudflare 运行时配置如下；私钥和连接密钥不要发到聊天或提交 Git：

| 名称 | 用途 |
| --- | --- |
| `GITHUB_APP_ID` | GitHub App 的数字 App ID，普通运行时变量 |
| `GITHUB_APP_INSTALLATION_ID` | 安装到 Wzz79229 的数字安装 ID，普通运行时变量 |
| `GITHUB_APP_PRIVATE_KEY` | GitHub 下载的完整 PEM 私钥，运行时 Secret |
| `QNH_CONNECTOR_KEY` | 仅历史电脑桥接使用的独立 Secret；当前手机流程无需设置 |
| `MEMBER_AUTH_MODE` | `qnh`，已在 wrangler.toml 声明；只有确认手机的牵牛花登录和实际租户后才开放业务访问 |

员工不填写 GitHub 令牌、连接密钥或团队口令。安装访问凭据在后台内存中自动获取及刷新，不提供给前端。`/api/session` 实际验证安装和受限令牌签发，通过时返回 `githubAuthorization:ready`，手机登录绑定可用时返回 `qnh_browser`，并按实际手机会话返回授权状态；该检查不读取业务文件，不能把 GitHub 授权通过当成员工登录或批次保存验收。旧 PAT 和团队会话仅保留明确的 legacy 模式兼容，生产部署使用 qnh 模式。

Cloudflare Git Build 根目录 `apps/qnh-shelf-life/backend`，构建命令只将部署产物 `../dist/connection.json` 的 `apiBase` 改为 `/`，部署命令 `npx wrangler deploy`。API 和 PWA 同域，避免手机跨站 Cookie 限制。公开 Pages 的连接文件只含公开 Worker 地址，不含 Secret。

## GitHub 数据位置

| 内容 | 仓库位置 |
| --- | --- |
| 源代码、测试、本机程序 | 公开 `Wzz79229/qnh/apps/qnh-shelf-life/` |
| Pages 文件 | 公开 `Wzz79229/qnh/docs/shelf-life/` |
| 正式批次 | 私有 `Wzz79229/bzq/main/data/tenants/<可信租户编号>/shelf-life.json` |
| 历史兼容查询队列（手机主流程不使用） | 私有 `Wzz79229/bzq/main/data/qnh-queries.json` |

批次记录 SKU/SPU、商品名称及规格用于对应商品，保存生产日期、保质期、件数和计算的到期日。商品图片只在本次查询/核对界面显示，不下载或另存图片文件；包装拍照不归档。原有历史批次、历史照片引用和旧快照不删除；旧接口仅保留兼容，新流程不读取整库、不新增包装图片。

历史电脑桥接查询文件最多 20 个任务，每个任务有效 5 分钟，电脑一次领取一个 60 秒租约。文件包含本次 SKU 和单个结果，不作为全量商品库；过期任务在新请求时回收，GitHub 提交历史仍会保留。严格使用预期 SHA 防止队列和批次互相覆盖；只有明确版本冲突才有限重试，写入结果不确定时不自动重复提交。

商品结果和业务 API 不进入 Service Worker 缓存。图片只接受页面实际显示的无凭据、无查询串的 HTTPS `img.meituan.net` 地址，不猜图片或匹配网络图片。登录输入只临时转发到员工正在操作的官方牵牛花页面，不记录、不写入 GitHub 或持久化存储；牵牛花 Cookie 只在独立云浏览器内存中使用，不返回手机。业务查询只提取对应商品资料，不读取价格或客户资料。

## 本地验证

Node.js 20+。启动主 App 不需要安装依赖；运行测试前用 `npm ci` 安装固定版本的开发测试工具（esbuild 仅用于验证 Worker 打包后的浏览器脚本，不随手机 App 加载）：

```powershell
npm start
# 运行回归测试
npm ci
npm test
```

本机预览 http://127.0.0.1:4173 仅此电脑可访问。`local-query/` 单独使用锁定的官方 Playwright 依赖；主 App 内置 ZXing 0.23.0 用于本地扫码，以及 Tesseract.js/core 7.0.0 和简中/英文模型用于本地 OCR，来源和许可证在对应 `dist/vendor/` 目录。

测试覆盖精确长 SKU、错误 SKU、队列 CAS/租约/取消/超时、牵牛花可见 DOM 与嵌套规格、日期冲突、月末和闰年、清点件数及照片临时释放。模拟测试不能替代真实登录、摄像头权限、移动端会话和 GitHub 读写的实机验收。`artifacts/` 中合成页面只用于本机测试，不发布，不写真实仓库。
