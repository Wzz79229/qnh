# 鲜期 · 拍照保质期管理

从牵牛花商品快照选择商品，拍包装识别生产日期与保质期，确认后建立商品批次；也可直接拍包装名称与日期。日常页面没有手动商品录入、表格导入或 GitHub 令牌填写。

## 拍照使用

1. 可先打开“商品库”，搜索名称、规格、条码或 SKU，核对图片及规格后点“选择并拍照”；未选商品时，点“拍照建档”并拍清包装上的产品名称或品名标签。
2. 日期和保质期不在同一位置时可补拍；同一批次最多 3 张。
3. 点“识别包装信息”。照片在浏览器本地运行 OCR，不发送到第三方识别服务，不需要 AI 接口令牌。
4. 核对只读结果。已明确选择商品时，名称和规格来自商品快照，日期仍须由包装识别。日期含糊、多个日期冲突或必需信息缺失时请补拍，不猜测或手动补写。
5. 团队后台连接成功时确认保存；尚未连接时只能“确认，暂存本页”，可下载含压缩照片的草稿备份。

每次确认建立一个拍照批次，不推断实际库存数量。默认紧急临期 7 天、即将临期 30 天；日期按北京时间计算，到期当天单独提醒。明确标注的到期日期优先，按月或年计算时超出目标月份天数取月末；请始终核对包装实际截止日。

## 牵牛花商品快照

商品库读取经过授权的私有仓库快照，不是牵牛花实时接口。页面展示同步时间、来源范围与 `source.complete`；`false` 明确显示“仅已采集部分 · 尚未确认完整”。未连接或读取失败会显示“尚未加载”，不把它当成空商品库。

商品清单与商品图片需分别取得并核对。图片地址缺失时显示占位，加载失败时显示不可用；不会凭名称匹配网络图片。当前是否有图及覆盖范围以实际快照为准，不能仅凭商品清单已取得就宣称图片完整。图片仅接受无凭据、无查询参数的 HTTPS `img.meituan.net` 地址。

商品名称、规格、SKU、SPU、类目和条码来自同一商品快照。识别包装条码后，只有唯一对应商品才会自动关联；同条码多个商品或名称候选都需要明确点选。SKU 不充当商品条码。批次保存可选 `productSku`、`productSpu` 和 `spec`，生产日期、保质期及到期日期始终保留包装证据，不由商品主档推断。

商品库经会话授权后逐页读取，核对同一 `generation`、来源和数量，全部通过后才显示；搜索覆盖已加载快照的全部商品。商品库只在本页内存中保存，退出团队会清除；商品资料、图片和 API 响应不进入 Service Worker 缓存。

## 管理员一次配置

`backend/` 提供固定读写 bzq 的 Cloudflare Worker，部署与 Secret 配置见 [backend/README.md](backend/README.md)。成员不需要 GitHub 令牌；后台独立保管一次管理员授权。

Cloudflare 将 PWA 和 API 放在同一个 Worker 域名，避免手机第三方 Cookie 限制。Git Build 使用 `apps/qnh-shelf-life/backend` 为根目录，构建时仅将 Cloudflare 部署产物 `../dist/connection.json` 的 `apiBase` 改为 `/`；GitHub 源码及 Pages 的空连接配置不变。具体命令见后台说明。管理员配置 Secret 后，还需验收团队登录、照片保存及另一台手机读取。源码和业务数据继续在 GitHub，后台不另建业务数据库。

没有配置后台就不声称已经自动连接。不要将 GitHub 令牌、团队密码或会话密钥发到聊天、放入前端文件或提交到 Git。

## 本地运行与验证

需要 Node.js 20 或更新版本，无需 npm install。

```powershell
npm start
npm test
```

本机预览 <http://127.0.0.1:4173>，只监听本机。测试涵盖日期、包装文字歧义、图片限制、后台会话、私有照片、商品快照校验、检索、条码歧义和数据版本冲突等；后端测试使用模拟请求，不能替代真实授权部署验收。本机合成商品库视觉工具仅放在忽略的 `artifacts/` 中，不属于部署内容或真实商品快照。

首次拍照识别按设备能力只选一种内嵌 WASM 的 LSTM core，再读取简中、英文两个 gzip 语言文件及 worker 脚本，文件合计约 7.8 MB（约 8 MB，实际传输量受 HTTP 压缩影响）。其他 core 变体和独立 `.wasm` 是保留的上游资源，不会全部下载用于一次识别。界面先缓存，OCR 资源使用后缓存；照片、业务接口响应和授权信息不进 Service Worker 缓存。苹果使用 Safari 分享菜单添加到主屏幕，安卓可在浏览器菜单安装或添加到桌面。

## 维护与依赖
