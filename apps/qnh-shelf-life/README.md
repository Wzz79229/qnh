# 鲜期 · 扫 SKU 管理保质期

扫描牵牛花 SKU，实时查回商品名称、规格和图片；拍摄生产日期与保质期，由员工清点填写件数，自动计算到期日期并保存批次。

正式手机入口：https://qnh-shelf-life-api.w792294944.workers.dev/ 。苹果使用 Safari 分享菜单添加到主屏幕，安卓从浏览器安装或添加到桌面。GitHub Pages 入口 https://wzz79229.github.io/qnh/shelf-life/ 也保留；苹果等限制第三方 Cookie 的浏览器请使用前面的同域入口。

## 先接入牵牛花

现可单独运行 [local-query/连接牵牛花.cmd](local-query/连接牵牛花.cmd)，在独立 Edge 窗口亲自登录牵牛花、进入商品主档，然后按提示输入 SKU，核对查回的名称、规格和主图。此入口无需 GitHub 令牌或 Cloudflare 连接密钥，不保存商品查询结果。详细步骤见 [本机连接说明](local-query/README.md#先连接牵牛花)。

2026-10-17，用户已通过此入口完成独立 Edge 登录与真实 SKU 查询，确认返回名称、规格和图片链接。电脑端查询已验证；手机端桥接、牵牛花身份绑定与 GitHub 自动保存仍待接通。

这是电脑商品查询的独立验证入口。员工手机的牵牛花单点登录尚未实现，批次保存仍需后台仓库授权；不能将本机已登录视为所有手机已有保存权限。目标使用流程为员工登录牵牛花后查询与保存，不再另设员工团队口令，现有线上身份层仍待替换。

## 使用流程

1. 登录团队，点“扫描 SKU 建档”。可实时相机扫码，也可拍 SKU 码；支持扫描枪输入或粘贴 SKU。
2. 点“查询牵牛花”，等待本机程序查回精确 SKU 的商品名称、规格和页面实际提供的商品图片。普通商品条码不会当成 SKU。编号始终作为字符串，保留前导零和长编号。
3. 核对商品后，拍清包装上的生产日期和保质期；可分开补拍，最多 3 张。照片仅在手机本页内存里用于 OCR，不上传，不进入备份或新批次，不保存到 GitHub；确认或关闭后释放临时照片。
4. 员工清点后填写这一生产日期的件数。必填 1 至 1000000 的整数，不从包装净含量推算，也不默认 1 件。
5. 核对生产日期、保质期和计算出的到期日期后保存。同 SKU 的不同生产日期分别建批次；重复 SKU 和生产日期会要求核对，不自动合并数量。

到期日期按生产日期加保质期计算。天按日历天计算，月/年超出目标月天数时取月末。生产日期在未来、日期或单位缺失、多个识别值冲突，以及包装明确到期日与计算值冲突时不能保存，须补拍。到期当天单独提醒；默认紧急临期 7 天、即将临期 30 天。

## 实时查询和本机程序

不再加载、搜索或同步整份商品库。每次扫码都创建新查询，由 `local-query/` 的程序在本机独立 Edge/Chrome 中操作可见牵牛花商品主档的 SKU 查询，只读取对应商品字段。未找到、多个匹配、登录失效、缺图、页面变更和超时会明确失败，不从旧快照回退。

本机程序只通过 HTTPS 出站领取查询和返回结果，无公网隧道，不消耗 Cloudflare 云浏览器时长。电脑需开机、联网，查询程序和牵牛花登录须保持可用。独立浏览器第一次需要管理员本人登录，不能复用应用内浏览器或日常浏览器的登录目录。

安装、密钥配置与启动见 [local-query/README.md](local-query/README.md)。源码和模拟测试完成不代表电脑连接或真实手机到牵牛花查询已经验收；需管理员完成下述配置、启动程序并实际查询后确认。

## 管理员配置

Cloudflare 现有 `qnh-shelf-life-api` 需要四个 Secret；值由管理员自行填写，不发到聊天，也不放进前端或 GitHub：

| 名称 | 用途 |
| --- | --- |
| `GITHUB_TOKEN` | 仅私有 `Wzz79229/bzq` 的 Contents 读写权限 |
| `TEAM_PASSWORD` | 至少 12 位的团队访问口令 |
| `SESSION_SECRET` | 至少 32 位的独立随机会话签名密钥 |
| `QNH_CONNECTOR_KEY` | 至少 32 位、无空白的独立随机连接密钥，本机程序使用同一个值；不能与上面三个值相同 |

成员只登录团队，不填写 GitHub 令牌或电脑连接密钥。后台配置不满足时明确显示未完成，不能把部署成功当成已连接私有数据。先查看 `/api/session`，再验收团队登录、本机实时 SKU 查询、批次保存和另一台手机读取。

Cloudflare Git Build 根目录 `apps/qnh-shelf-life/backend`，构建命令只将部署产物 `../dist/connection.json` 的 `apiBase` 改为 `/`，部署命令 `npx wrangler deploy`。API 和 PWA 同域，避免手机跨站 Cookie 限制。公开 Pages 的连接文件只含公开 Worker 地址，不含 Secret。

## GitHub 数据位置

| 内容 | 仓库位置 |
| --- | --- |
| 源代码、测试、本机程序 | 公开 `Wzz79229/qnh/apps/qnh-shelf-life/` |
| Pages 文件 | 公开 `Wzz79229/qnh/docs/shelf-life/` |
| 正式批次 | 私有 `Wzz79229/bzq/main/data/shelf-life.json` |
| 按需查询任务 | 私有 `Wzz79229/bzq/main/data/qnh-queries.json` |

批次记录 SKU/SPU、商品名称及规格用于对应商品，保存生产日期、保质期、件数和计算的到期日。商品图片只在本次查询/核对界面显示，不下载或另存图片文件；包装拍照不归档。原有历史批次、历史照片引用和旧快照不删除；旧接口仅保留兼容，新流程不读取整库、不新增包装图片。

查询文件最多 20 个任务，每个任务有效 5 分钟，电脑一次领取一个 60 秒租约。文件包含本次 SKU 和单个结果，不作为全量商品库；过期任务在新请求时回收，GitHub 提交历史仍会保留。严格使用预期 SHA 防止队列和批次互相覆盖；只有明确版本冲突才有限重试，写入结果不确定时不自动重复提交。

商品结果和业务 API 不进入 Service Worker 缓存。图片只接受页面实际显示的无凭据、无查询串的 HTTPS `img.meituan.net` 地址，不猜图片或匹配网络图片。整个流程不读取、上传牵牛花账号密码、Cookie、存储快照、价格或客户资料。
